Chapter 5: Publishing Your Website

Introduction

Publishing your website allows you to share your work with the world. In this chapter, you will learn about traditional and modern methods of website publishing, including FTP, cloud hosting services, and GitHub Pages. You will also learn how to organize project files cleanly and get hands-on experience publishing a live website using GitHub Pages.

Overview of FTP and Secure FTP (SFTP)

What is FTP?

File Transfer Protocol (FTP) is a standard network protocol used to transfer files from a local computer to a web server. It has been a fundamental tool for website publishing since the early days of the internet. However, standard FTP sends data and passwords unencrypted, making it vulnerable to unauthorized interception.

Secure FTP (SFTP)

SFTP (Secure File Transfer Protocol) is a secure alternative to FTP that encrypts file transfers using SSH (Secure Shell). This protects login credentials and website files in transit, making SFTP the preferred choice when uploading files manually to a web host.

Using FTP/SFTP to Upload a Website

To upload a website using FTP or SFTP, follow these steps:

  1. Choose an SFTP Client: Applications such as FileZilla or Cyberduck connect your computer to a remote web server.
  2. Connect to Your Web Host: Enter your hosting provider’s server address, port, and SFTP credentials.
  3. Upload Your Files: Drag and drop your website files into the server’s public directory (commonly named public_html or www).
  4. Verify Your Website: Open a web browser and visit your domain name to confirm that your pages load properly.

Modern Methods for Publishing a Website

While SFTP remains useful for traditional hosting, modern web development offers faster, version-controlled deployment workflows:

1. Cloud Hosting Services

Cloud platforms such as AWS, Google Cloud, and Microsoft Azure offer automated deployments, CDNs (Content Delivery Networks) for fast global delivery, and scalable storage. Many integrate directly with Git repositories.

2. Static Site Hosting

Platforms such as GitHub Pages, Netlify, and Vercel connect to a Git repository and automatically publish the latest version of your HTML, CSS, and JavaScript files whenever you save updates.

3. CMS-Based Hosting

For websites built with a CMS (Content Management System) like WordPress, Wix, or Squarespace, hosting and publishing are built directly into the platform.

What is Git?

Git is a distributed VCS (Version Control System) created by Linus Torvalds in 2005 that helps developers track changes to files and collaborate on projects. Git keeps a complete history of edits so multiple contributors can work on the same codebase without overwriting each other’s work.

Organizing Your Website

A clean, predictable folder structure keeps your links working when you move files from your computer to a live server and prepares your project for external CSS stylesheets in Chapter 6.

1. Use a Clear Folder Structure

  • Store your main homepage in the root folder as index.html (web servers automatically look for index.html as the default landing page).
  • Keep stylesheets in a css/ folder (for example, css/style.css).
  • Store JavaScript files in a js/ folder.
  • Place images and media files in an images/ folder.

2. Follow Strict Naming Conventions

  • Use all lowercase letters and hyphens instead of spaces (for example, about-us.html rather than About Us.html).
  • Keep file and folder names short, descriptive, and consistent.

3. Use External Stylesheets and Scripts

  • Keep CSS and JavaScript in external files linked from your HTML rather than repeating inline styles on every page.
  • This separation makes multi-page websites far easier to read and maintain.

4. Organize Content Logically

  • Provide a consistent navigation menu across every page on your site.
  • Group related assets together so relative file paths stay simple.

Important Deployment Tip — Case Sensitivity on Web Servers: Windows and macOS often ignore capitalization when opening local files, so Images/Logo.png might still load on your laptop. However, GitHub Pages and most web servers run on Linux, which is strictly case-sensitive—meaning Logo.png and logo.png are treated as two different files and mismatched capitalization will cause a 404 Not Found error.

Introduction to GitHub Pages for Free Hosting

GitHub Pages is a free hosting service offered by GitHub that publishes static websites directly from a GitHub repository. It supports HTML, CSS, and JavaScript, making it ideal for student portfolios, documentation, and personal websites.

How GitHub Repository Names Determine Your Live URL
Site Type Repository Name Format Resulting Live GitHub Pages URL
Personal / Root Site (one per account) <your-username>.github.io https://<your-username>.github.io/
Project Site (unlimited per account) Any project name (e.g., my-website) https://<your-username>.github.io/my-website/

Step-by-Step Guide to Publishing a Web Page

Step 1: Create a GitHub Account

Before you can publish a web page, you need a free GitHub account. Visit GitHub’s official website (opens in new tab) and complete the sign-up instructions.

Step 2: Create a New Repository

Once signed in, create a repository to store your website files:

  1. Click the + icon in the upper-right corner of GitHub and select New repository.
  2. Enter a repository name—either <your-username>.github.io for your main site or a project name such as my-website.
  3. Add an optional description and set visibility to Public (required for free GitHub Pages hosting).
  4. Optionally check Add a README file, then click Create repository.

Step 3: Add Your Web Page Files

Upload your site files to the repository root:

  • Directly in the Browser: Open your repository, click Add file, and choose Upload files. Drag and drop your index.html file (along with any css/ or images/ folders) and click Commit changes.

Step 4: Enable GitHub Pages

Turn on hosting in your repository settings:

  1. Open your repository on GitHub and click the Settings tab.
  2. In the left sidebar, select Pages.
  3. Under Build and deployment > Source, choose Deploy from a branch.
  4. Select your main branch and the / (root) folder, then click Save.

After a minute or two, refresh the Pages settings screen to see your live link at the top of the page.

Step 5: Customize and Update Your Web Page

Once your website is live, you can continue improving it:

  • Upload updated HTML, CSS, or image files whenever you make changes—GitHub Pages automatically rebuilds the live site.
  • Optionally connect a custom domain name under the Pages settings panel.

Your Turn: Publish a Simple Website Using GitHub Pages

Follow these steps to complete your hands-on deployment activity:

Step 1: Create and Upload Your Website

  1. Open VS Code, create a new file named index.html (all lowercase), and paste the following HTML5 starter template:
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>My GitHub Web Page</title>
</head>
<body>
    <h1>Hello!</h1>
    <p>Welcome to my live website hosted on GitHub Pages.</p>
</body>
</html>
  1. Save the file and upload it to a new GitHub repository named my-website, then enable GitHub Pages on the main branch.

Step 2: Verify Your Website

  1. Wait 1 to 2 minutes for GitHub Pages to finish building your deployment.
  2. Open a browser and visit https://<your-username>.github.io/my-website/ (replacing <your-username> with your GitHub username).
  3. Confirm that your heading and welcome paragraph appear properly.
